# Roadmap

Overdrive rewrites MediaChips (Electron + Vue 3 + Express + SQLite/drizzle)
as a native Rust app on iced 0.14 and colony-ui, conforming to
Project-Colony-Resources from the first commit.

The upstream code in `reference/mediachips/` is the functional spec: read the
relevant part before porting a feature, and port behaviour, not structure.

## Goals

- Feature parity with MediaChips v1.12.0 for the desktop use case, then
  better than it.
- A fully new UI built on colony-ui: sidebar navigation, Colony themes,
  typography, settings page, en/fr i18n (see Resources `design/*.md`).
- One raw binary per platform, listed in the Colony store through
  `colony.json`, released with Release Please and signed by the shared
  workflow.
- Smooth on libraries of hundreds of thousands of files.

## Non-goals

- No activation key, license server, device limit or unregistered mode.
  Everything upstream gates behind registration is simply available.
- No telemetry, no cloud, no account.
- Not a port of the Electron or Express architecture.

## Constraints

- **License:** GPL-3.0-only, because upstream is GPL-3.0 and we cannot add
  "or later" without the copyright holders. This is the one exception to the
  org's GPL-3.0-or-later rule. Keep upstream copyright notices.
- **Repository layout:** follow Resources `design/repository-layout.md`.
  `reference/` is study material, never compiled, never edited.
- **Commits:** conventional commits, squash-merged PRs, at most 4 open PRs
  at a time, grouped by theme.
- **Builds:** at most 2 parallel cargo builds on the dev machine.

## Phase 0 - Foundation

- [ ] Cargo workspace per `design/repository-layout.md` (`crates/overdrive`
      binary, `crates/overdrive-core` for library, DB and scanning logic).
- [ ] colony-ui 0.1.6 dependency, app shell with sidebar navigation, theme,
      typography, en/fr strings, settings page skeleton.
- [ ] Runtime paths through the Colony filesystem helper
      (`design/filesystem.md`).
- [ ] `colony.json`, `release-please-config.json`,
      `.release-please-manifest.json`, `.github/workflows/release.yml` from
      Resources templates; Dependabot; CI (fmt, clippy, test) on the 3 OS.
- [ ] README sections `## Code signing policy` and `## Privacy` from
      `templates/program/README.md`.

## Phase 1 - Video spike (decision gate)

Inline playback is the main technical risk in iced. Settle it before building
the UI around it.

- [ ] Throwaway spike with `iced_video_player` 0.6.0 (iced 0.14, GStreamer
      0.23 bindings): play, pause, seek by dragging, loop, on MP4 / MKV /
      WebM / HEVC files from a real library.
- [ ] If GStreamer falls short (codecs, seek latency, NVIDIA + Wayland
      glitches), try libmpv's render API into a texture.
- [ ] Fallback in every case: "Open in external player" (mpv by default,
      configurable).
- [ ] Decide how ffmpeg and the player runtime ship under the single-binary
      rule (embed and extract on first run, as SAM Colony Edition's
      `bootstrap.rs` does, or require a system package on Linux).

Dev machine reference: Arch, Hyprland, NVIDIA; GStreamer 1.28.8 with base,
good, bad and libav plugins (no ugly); mpv 0.41; ffmpeg 9.0.2.

## Phase 2 - Data core

- [ ] SQLite schema ported from `reference/mediachips/api/db` (drizzle
      migrations): media, chips, chip types, tags, tag hierarchy, synonyms,
      filters, presets, markers, playlists.
- [ ] Importer for existing MediaChips databases, so current users keep their
      library.
- [ ] Folder scanner, watched folders, file identity (path + hash), metadata
      probing via ffprobe.
- [ ] Multiple databases, backup and restore.

## Phase 3 - Previews pipeline

- [ ] Background job queue with progress and cancel.
- [ ] Thumbnails, 3x3 storyboard grids, timeline scrub sprites, generated by
      ffmpeg and cached on disk.
- [ ] Hover preview and scrub on cards, image-based.
- [ ] Cache cleanup and regeneration.

## Phase 4 - Browse UI

- [ ] Browser layout: tags sidebar, media grid, inspector, docked filters.
- [ ] Media, tags and folders views; configurable cards.
- [ ] Filters on any field or tag, nested fields, exact and negative
      conditions; saved presets; sort and group-by.
- [ ] Global search (`/`).
- [ ] Virtualised grid that stays smooth at 100k+ items.

## Phase 5 - Chips and tags

- [ ] Built-in and custom chip types (tags, ratings, favorites, bookmarks,
      text, dates, numbers, colors).
- [ ] Tag profiles: images, countries, nested chips, synonyms, categories,
      hierarchy, merge.
- [ ] Chip recipes (port `reference/mediachips/chip-recipes/`).
- [ ] Path tags and regex extraction, bulk edit.

## Phase 6 - Player

- [ ] Built-in player (from the phase 1 decision) with timeline markers,
      chapters and playlists.
- [ ] Keyboard control by physical key position (AZERTY-safe).

## Phase 7 - Library tools

- [ ] Duplicate finder (fingerprint + visual grid).
- [ ] Image, audio and text media support at parity with upstream.

## Phase 8 - Integrations (scope to confirm)

Upstream ships JavaScript plugins (Stash, Jellyfin, Plex, Emby, TMDB, adult
scrapers). Decide which become built-in Rust importers and whether Overdrive
needs a plugin system at all. Stash import is the most valuable one.

## Phase 9 - Optional ML (scope to confirm)

CLIP scene search and on-device face tools (SCRFD, InsightFace) via ONNX
Runtime. Models downloaded on demand, never bundled.

## Phase 10 - Release

- [ ] First signed release; then `"signed": true` in `colony.json`.
- [ ] Conformity audit against all of Project-Colony-Resources.
- [ ] Before the repository goes public: move this roadmap out of the
      repository (GitHub issues or milestones) and check history for anything
      that must not be public.

## Open decisions

- New features and improvements beyond parity: to be defined.
- LAN / mobile browser access and Docker / NAS mode from upstream: keep,
  drop, or later.
- Plugin system or built-in importers only (phase 8).
- ML features in or out (phase 9).
